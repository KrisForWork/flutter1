# Нагрузочный отчёт (клиент) — «Справочник»

**Тип нагрузки:** только клиентская (in-memory `DirectoryRepository.generate` / `filter`)  
**Не используем:** JMeter, k6, серверный load  
**Источник замеров:** `test/load/directory_repository_load_test.dart` (`Stopwatch`)  
**Дата:** 2026-09-11 (прогон REVIEWER)

## Среда

| Параметр | Значение |
|----------|----------|
| ОС | Windows 10 (build 26200) |
| Режим | `flutter test` (VM, без UI frame budget) |

## Таблица времени

| N | Операция | Время, мс | Результат |
|---|----------|-----------|-----------|
| 100 | `generate(100)` | 1 | count = 100 |
| 100 | `filter` (категория «Тестирование» + query «Запись») | 1 | length = 34 |
| 1 000 | `generate(1000)` | 3 | count = 1000 |
| 1 000 | `filter` | 1 | length = 334 |
| 10 000 | `generate(10000)` | 19 | count = 10000 |
| 10 000 | `filter` | 8 | length = 3334 |

> Повторные прогоны дают разброс порядка нескольких мс (например generate_10000 ≈ 16–19, filter_10000 ≈ 8–15).

## Widget-нагрузка (UI)

| N | Где | Комментарий |
|---|-----|-------------|
| 100 | `test/widget/load_page_test.dart` | Выбор N, генерация, `load_result_text` |
| 1 000 / 10 000 | экран «Нагрузка» + load-unit | Логика покрыта; **скролл/FPS на устройстве не замерялись** |

## Выводы

1. Генерация и фильтрация до 10 000 записей на клиенте укладываются в десятки миллисекунд (логика без UI).  
2. Узкое место при реальном использовании — отрисовка списка; в приложении — `ListView.builder`, кэш фильтра в контроллере.  
3. Это **клиентская** нагрузка, не серверный JMeter/k6.

## Повтор прогона

```bash
flutter test test/load/directory_repository_load_test.dart
```
